# D.E.R.S. v1.1.2 - Control & Polish Update

Release preparation: 18 October 2026. Production publication, the additive admin
schema, the private server-side backup and the named admin membership were
explicitly approved by the user. The release is limited to v1.1.2.

## Scope

- Saydam replaces the visible Bulanik label. The stored classic/glass preference
  remains compatible. Glass alpha, backdrop blur and muted text contrast work
  with preset and uploaded backgrounds; Classic keeps its previous surfaces.
- Admin access uses a database-controlled private membership list. Neither the
  public account role nor editable Auth metadata can grant admin privileges.
- Student/teacher previews reuse the actual application inside an opaque-origin
  sandbox. They receive synthetic fixtures and memory storage, never Auth tokens.
  CSP blocks API, worker, frame and form navigation requests from the sandbox.
  Public JS/CSS/background assets are fetched by the authenticated parent and
  embedded in the frame, so protected Vercel previews need no frame credentials.
- Reset rebuilds only the open synthetic preview. It cannot delete accounts,
  real programs, notes, XP, history or teacher connections.
- Private test notes include type, role context, screen, description and server
  date. Failed saves preserve the text; retry IDs prevent duplicate notes.
- Private operation history records panel opening, preview requests, returning,
  sample reset requests and note saves. Notes create their event in the database.
  Events contain typed actions/context/server dates, without note text or tokens.
  Clients cannot forge event owners/timestamps, update or delete the events.
- Existing study history is grouped by week and Istanbul calendar day. Existing
  date, week and lesson filters, XP amounts and record IDs remain unchanged.
  The pre-existing 80-record display limit is retained.

## Preview Limits

Synthetic previews reset on role changes/closing and do not impersonate accounts.
Some external/server operations (for example real authentication and repeat
ledger requests) are deliberately not simulated. Custom device photos are not
copied into the sandbox. Notes and audit history are saved to the admin's account.
Physical-phone installation was not part of this scoped update.
